What is a backend?

It's the part of the website that remembers things, checks who is allowed in, and keeps promises about the rules even after you close your browser.

Think of it as a small community building, not a mysterious cloud.

01 · The building

Firebox

The Node program that accepts visitors, checks permission, and runs the actual rules. It's a program running on one computer.

02 · The logbook

Memory

One SQLite database file on that computer keeps the circles, messages, needs, and reported outcomes across restarts.

03 · The keys

Gatekeeper

One-use invitations give a participant a private key. The firebox decides what that particular key may read and change.

04 · The room

Campfire

The page on your phone. People talk, offer, report, and separately accept a report. The web page is the door, not the logbook.

Waggle dance · heartbeat 001

That check asks the computer serving this page whether its program is responding. It does not claim the disk is backed up, the server is publicly available, a human is verified, or help was physically delivered.

Does it have to live on this computer forever?

No. The software can move to another computer. We would need to move the protected logbook and keep exactly one authoritative writer while the switch happens. We should not have several independent copies pretending to be the same database.

Local mode

Run one command on a spare PC. The browser page opens on that machine. It's a great first test.

node campfire-backend/start.mjs

Hosted mode

Run the same Firebox on a protected server with real persistent storage and HTTPS. It can then serve phones anywhere the service is authorized.

Waggle mode (future)

Stateless helpers may roam, look for opportunities, and carry approved public-safe hints. They cannot carry or fork the private logbook or claim a delivery was confirmed.

Modal reality check: Modal can host Node web servers, but Modal Volumes have explicit synchronization and concurrent-writer limitations. We should not casually run a writable SQLite/WAL logbook across autoscaling Modal containers. Before a Modal release, the durable single-writer boundary needs an appropriate design.

What do I actually have to do?

I want to test it on one computer.

Get the code from the NanaSpork project, use Node 22.13+, run node campfire-backend/start.mjs, and open http://127.0.0.1:3417/. It creates its own private logbook and operator key. No external database account.

I want two people to join.

Make a circle and two separate one-time invitations with the included operator command. People must keep their own keys private. Remote phones additionally need a secure HTTPS connection to the server. Nobody is enrolled automatically.

How do I know what it remembered?

On the host computer, type node campfire-backend/manage.mjs status. It describes the live database in everyday language and checks the local audit chain. The operator key stays on the host.

What if my computer turns off?

Other people can't reach it until it's running again. Messages already written to its private database survive an ordinary restart. Without a separate tested backup, disk failure could still lose data.

Does pressing “accepted” prove actual food was delivered?

No. It proves that the credential assigned to the need's owner accepted a reported quantity in the system. Physical delivery and independent recipient identity need separate evidence.

Can people safely share survivor stories or custody records here?

Not yet. This first version keeps message text readable on the server disk and has not passed a sensitive-data security review. Use fictional test information only.
