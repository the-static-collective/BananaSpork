# HELP-SLIP-GARDEN-ADAPTER-001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let NanaSpork/Garden privately HOLD Band Runtime-compatible Nourish Help Slips, then explicitly POUR selected requirements into the existing authenticated Campfire lifecycle.

**Architecture:** Add a focused `src/domain/help-slip/` domain for strict import/hash compatibility, local HOLD persistence, per-requirement POUR, lineage links, and residuals. Extend Jubilee with one narrow `openSharedNeed` command that preserves quantity/unit and never fabricates an authority ID. Garden/Today provides the human-facing inbox; no new backend schema or live Band Runtime dependency.

**Tech Stack:** React 19, TypeScript 5.8, Vite 6, Capacitor 8, Supabase JS, @noble/hashes, Node 22 + tsx.

**Spec:** `docs/superpowers/specs/2026-09-18-help-slip-garden-adapter-001-design.md`

## Global Constraints

- `RECEIVE != HOLD != POUR`; import/HOLD never calls Supabase.
- Imported payload is immutable; duplicate arrivals reuse one case by `payloadHash`.
- Help Slip hashing matches Band Runtime's schema-order serializer; do not use NanaSpork's alphabetical `canonicalJson`.
- POUR is per requirement. Preserve source quantity/unit exactly; no conversion.
- Qualitative requirement -> `targetUnits: 1`, `unitLabel: "item"` with visible notice.
- Recipe/envelope/hash/source metadata stays local by default.
- Shared publication uses existing Jubilee -> `rpc_open_need`.
- Store a lineage link only after a real authority need ID returns.
- Refresh failure after authority success must never cause a second open.
- `fulfillment.reported != fulfillment.confirmed`.
- Held content stays out of Gemini, BananaBot, Intelligence, Porch, and Jubilee receipts by default.
- No QR, matching, ranking, reputation, payments, cross-device HOLD sync, backend migration, or new runtime dependency.
